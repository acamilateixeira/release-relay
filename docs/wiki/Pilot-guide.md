# Pilot guide

## Who to interview

Start with five freelancers or small agencies that ship websites regularly, can show a recent client handoff and use GitHub Actions on at least some projects. Look for repeated questions about what shipped, approval status or evidence of the review.

## Conversation and demo

1. Ask for the last real delivery. Where did the revision, validation checklist and customer message live?
2. Ask who prepared the update, how long it took, and what follow-up the client needed.
3. Show the sample workflow. Pick a commit, complete a review, publish one handoff and open the client view.
4. Ask the person to identify the revision, what was verified and the next step from the link alone.
5. Offer to run one upcoming public-repo delivery as a paid pilot. Agree the scope, support window, price and date with the agency.

## What to record

Track how long it takes to get from a first sync to a published handoff, whether the client opens it, what follow-up questions remain, and how much support was needed. Ask whether the agency would use it on another delivery. A paid pilot and repeat use are separate signals.

Pilot invitation to adapt for a conversation:

> Want to use Release Relay on your next client release? We can set up one public GitHub project, prepare a reviewed handoff and see how it fits your workflow. If you have a delivery coming up, we can agree on the scope and a fixed pilot price.
