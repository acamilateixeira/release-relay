# Contributing and roadmap

## Contribute

1. Open an issue with the user problem, expected behavior and a reproducible example.
2. Make a small branch from `main`. Run the relevant tests and verify the original failure.
3. Open a PR with the affected workflow, test evidence and any data or access implications.
4. Update the English and Portuguese READMEs when setup or user-facing behavior changes. Update the relevant Wiki page and collection in the same PR.
5. For AI-assisted changes, record what was generated, what was corrected during review, and how the result was checked.

Keep the Wiki source in `docs/wiki/` for code review. The GitHub Wiki is the reader-facing mirror. Update it after the documentation change reaches `main`.

## Milestones

| Milestone | Evidence |
| --- | --- |
| Local contract | Synthetic workflow, incomplete review rejection, publication and revocation. |
| Lovable MVP | Usable no-account demo, authenticated projects, real public run import and owner isolation. |
| Agency pilot | A real release from one agency, delivered through the shared link and paid for by the agency. |
| Integration expansion | Review pilot evidence before adding private repos, installation-based access or wider billing. |

See [Pilot guide](Pilot-guide.md) for how to validate the business case.
